# v11.0 — Production Environment Plan

| Field | Value |
|---|---|
| Status | PLANNED — authorized for planning only, implementation per-phase on approval |
| Scope | Full production hardening: containerize, configure, proxy/TLS, persist/backup, observe, secure, release |
| Milestone | `v11.0` — Production Environment (`Production` era, `pending`) |
| Spec | This document is the plan; PCS/UX/ATS remain prerequisites before build phases |
| Last Updated | 2026-10-12 |

> Current state (evidence, 2026-10-12): no `Dockerfile`/`docker-compose` in repo (glob empty),
> `os/systemd/` owns 9 units (`vestara-api.service`, `vestara-workspace.service`, `opencode-server.*`),
> CI is `build → lint → test → benchmark` only (no image publish, no prod deploy),
> runtime config is env-var driven (`VESTARA_REPO`, `VESTARA_API_PORT`, `VITE_API_URL`, `.env` gitignored, `--env-file=.env`),
> API is HTTP+WS gateway (`apps/api/src/index.ts`), UI is Vite SPA proxied via `apps/workspace/vite.config.ts`.
> Gaps: no reproducible prod image, no TLS/reverse-proxy, no backup/restore, no prod observability,
> no rate-limit/CORS hardening inventory, no release/signing pipeline.

## 0. Non-goals / invariants

- Activity Room remains projection/control surface — this milestone adds no execution authority.
- No deep internal imports (`@vestara/<pkg>` only), no package → `apps/*` dependency, no cycles
  (`pnpm dependencies:check` stays green).
- No `style=` hex / `bg-[#...]` / arbitrary values in any UI/runbook page touched — tokens via `var(--vestara-*)`.
- `.vestara/` runtime state is never hand-edited; prod mounts it as a named volume.
- `.env` contents are never committed; prod uses an env-file or secrets manager, validated at boot.

## 1. Phase 0 — Baseline audit (0.5 day, zero mutation)

1. Inventory: `os/systemd/*`, `apps/api/dist` boot path, `VESTARA_*` env reads (`rg VESTARA_`), `.env.example` absence, SQLite files (`.vestara/`, `*.sqlite`), WS routes (`/ws`), public vs authed routes (`auth-enforcement.test.ts`).
2. Record in plan appendix: ports (3001 API, 5173 dev UI, 4096 OpenCode, 3002 mock), volumes, existing health (`/api/health`), current `doctor` latency, benchmark baselines.
3. Gate: audit table committed; no code changes.

## 2. Phase 1 — Containerization (1–2 days)

- `apps/api/Dockerfile` (multi-stage `node:22-slim`, `pnpm --frozen-lockfile`, `build-order.sh`, non-root `vestara`, `HEALTHCHECK CMD node -e "fetch('http://127.0.0.1:3001/api/health')"`).
- `apps/workspace/Dockerfile` (build stage `tsc -b && vite build`, runtime `nginx:alpine` serving `dist/` + `/api`+`/ws` proxy).
- `docker-compose.prod.yml`: `api` (env-file, `vestara-data:/app/.vestara`, restart unless-stopped), `ui` (depends_on api), `opencode` (existing supervisor contract), shared network, named volumes.
- `pnpm check:source-artifacts` + `.dockerignore` (`node_modules`, `dist`, `docs/api`, `*.sqlite` excluded from context).

Acceptance: `docker compose -f docker-compose.prod.yml build && up -d && curl -f http://127.0.0.1:3001/api/health`.

## 3. Phase 2 — Env & config authority (0.5–1 day)

- Add `.env.production.example` (`VESTARA_API_PORT`, `VESTARA_REPO`, `VESTARA_API_KEY`, `VITE_API_URL`, `VESTARA_BROWSER_DRIVER`); document trailing-slash trim rule.
- Zod-validated boot config in `@vestara/configuration`: fail-fast on missing/invalid prod keys, `doctor` surfaces which key failed (no secret echo).
- `VESTARA_REPO` volume-mount contract: single repo per container; multi-repo stays `org` CLI, not prod topology.

Acceptance: missing key → non-zero exit + actionable message; `vestara doctor` green on valid env.

## 4. Phase 3 — Reverse proxy + TLS (1 day)

- Caddy (default) or nginx profile in compose: `:80`/`:443` → `ui:80`, `/api/*`+`/ws` → `api:3001`; security headers (`HSTS`, `X-Content-Type-Options`, `frame-ancestors`), access logs.
- WS upgrade preserved; SSE disconnect still ≠ cancellation (existing lifecycle invariant).
- Dev parity: `vite.config.ts` proxy stays dev-only; prod never uses Vite dev server.

Acceptance: `https://<host>/api/health` 200, WS chat + REPL stream survive proxy, headers present.

## 5. Phase 4 — Persistence & backup (1 day)

- Named volumes: `vestara-data` (`.vestara/`, sqlite DBs), `vestara-workspace` (checked-out repos); mount docs + retention policy.
- `scripts/backup-vestara.sh` (sqlite `.backup` + tar + checksum) and `scripts/restore-vestara.sh` (verify checksum → restore → `doctor`); cron/systemd-timer example.
- Disaster drill: stop → wipe volume → restore → `pnpm vestara doctor` + smoke `open → explain → plan` deterministic tiers.

Acceptance: backup/restore round-trip on staging with checksums logged.

## 6. Phase 5 — Observability (1 day)

- Structured JSON logs (existing logger), `/api/health` + per-service latency (existing `doctor` fields) scraped; uptime probe every 30s.
- CI benchmark gate already exists — add prod smoke job: `compose up -d → /api/health → /api/opencode/config → compose down`.
- Runbook `docs/operations/PRODUCTION-RUNBOOK.md`: ports, volumes, env table, `services:status`, log locations, restart order (opencode → api → ui/proxy).

Acceptance: runbook exists; smoke job green; logs contain no secrets.

## 7. Phase 6 — Security hardening (1 day)

- Keep fail-closed auth (`auth-enforcement.test.ts` green); audit public routes list; CORS allowlist by env; rate-limit `/api/chat/*` + `/api/auth/*`.
- Non-root images, read-only rootfs where possible, `no-new-privileges`; `pnpm audit` / dependency review in release job; secret isolation (keys via env-file only, never baked into layers — verify with `docker history --no-trunc` + `rg` on image).
- Align with `SECURITY.md` reporting policy.

Acceptance: unauthenticated `GET /api/milestones` → 401; image contains no secret literals.

## 8. Phase 7 — Release pipeline (1 day)

- Tag scheme `v11.0.x`; `CHANGELOG` entry; image tags `vestara-api:v11.0.x` + `vestara-ui:v11.0.x` with sha + checksum manifest; rollback = previous tag + volume restore (documented, drilled once).
- Extend `.github/workflows/ci.yml` with `prod-image` job (build only on tags; push on approval) — advisory until registry decision lands.

Acceptance: tag build produces checksummed images; rollback procedure executed once on staging.

## Verification (per release)

- `pnpm lint:check && bash build-order.sh && pnpm test:fast` green.
- `pnpm dependencies:check` + `pnpm check:source-artifacts` green.
- `docker compose -f docker-compose.prod.yml up -d` + `curl -f /api/health` + authed `/api/milestones` 200 + unauthenticated 401.
- `docs:validate` frontmatter/links pass for new docs; `scripts/milestone-status.sh v11.0` reports planned phases.
