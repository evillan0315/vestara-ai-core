# AR-P1.5 — Authority Contracts (Target Boundaries)

> **Status:** Proposed contracts — no migrations, no store consolidation, no OpenCode behavior change, no legacy-path removal in this document. All changes are *specification only*.
> **Evidence:** `docs/AR-P1-AUDIT.md` (2026-08-26, 10-transition call graph + ownership matrix)
> **Effective scope:** `vestara-ai-core` — `apps/api`, `packages/*`, `apps/workspace`
> **Version:** `AR-P1.5/1` — contracts are versioned; any AR-P2 implementation must cite this version.

---

## 0. Preamble & Non-Goals

### 0.1 What this document is

The authoritative boundary specification that **AR-P2 may implement** and **AR-P1.5 must not**. It turns the audit's duplicate-ownership findings into single-writer contracts, defines canonical identities, and freezes the Activity Projection as derived/append-only.

### 0.2 What this document is not

- Not a migration plan (migration order is listed in §10 for sequencing, not executed here).
- Not a store-consolidation design — `plans.db`, `threads/*.db`, `activity.db`, `conversations/*.db`, `routing.json` remain separate in AR-P1.5.
- Not an OpenCode server change — `openCodeSessionId` stays external; new Vestara identities wrap it.
- Not a UI redesign — UI may continue to call legacy ingresses in AR-P1.5; contracts only define which ingress is canonical going forward.

### 0.3 Requirement trace

> Provider/model selection must resolve through one Routing Authority. Agent definitions may express requirements/preferences but must not be final execution-selection authority.
> Runtime session identity must be provider/runtime-neutral. OpenCode session IDs are external implementation identifiers, not Vestara domain identities.
> Activity Projection remains append-only/derived and must never become authoritative for workflow, conversation, routing, runtime session, participant/presence, approval or acceptance state.

These three invariants are **hard constraints** on every contract below. Any AR-P2 PR that violates them fails review even if tests pass.

## 1. Design Principles (Authority Invariants)

| # | Invariant | Enforcement |
|---|---|---|
| **I-1** | **Single writer, single store** — every mutable domain fact has exactly one authority service and one persistence location. All other copies are derived projections, caches, or ephemeral views. | Authority matrix §9; CI check `ownership-matrix.json` (future) |
| **I-2** | **Append-only history, mutable current** — history (`activity.db`, `engineering-events.db`, `conversation_messages`) is immutable after write; current state (`plans.db` project/task row, `FileThreadStore` turn state, `routing.json` selection) is mutable under OCC or state-machine guards, and emits history. | Projects `reconcile()`/`rebuild()` vs Activity `project()` — inverse directions |
| **I-3** | **Routing is the only execution selector** — no caller may invoke a provider/model without a `RoutingDecision` token. Agent prefs, env defaults, and runtime discovery are *inputs* to Routing, never bypasses. | `Permitted callers` in each contract; review gate: `grep -r '\.complete(' -- packages/agent-harness` must show only via Routing facade |
| **I-4** | **Provider-neutral session identity** — Vestara's `runtimeSessionBindingId` is canonical; `openCodeSessionId` is an external correlation attribute. Vestara never persists an external ID as primary key. | Identity model §3 |
| **I-5** | **Projection never writes authority** — Activity Projection may project `workflow`, `task`, `acceptance` as activity kinds but must never `UPDATE` those authorities, decide approval, or own presence/participant lifecycle. | `Forbidden responsibilities` per authority |
| **I-6** | **Recovery is replay, not repair** — restart recovery replays durable history into derived state; it never silently mutates authoritative state to match derived. | Each authority's `Recovery semantics` |

## 2. Canonical Identity Model

### 2.1 Identity definitions

| Identity | Type | Format | Generated by | Uniqueness scope | Notes |
|---|---|---|---|---|---|
| `workspaceId` | workspace fingerprint | `string` — `WorkspaceRuntime.fingerprint.id` (`sha256(repoPath+...)` today) | `WorkspaceRuntime.open()` | Global (cross-workspace unique) | Stored in `.vestara/workspace.json`; passed as `workspaceId` in every binding. AR-P2 adds `project.directory` FK (see §4). |
| `conversationId` | conversation | `conv-{epochMs}-{counter}` | `DefaultConversationService.createConversation()` | Global | Owns its `Message[]` via `conversation_messages.conversation_id` FK. Not reused across workspaces. |
| `messageId` | message | Chat: `msg-{epochMs}-{counter}` / Activity: `activity:msg:${uuid}` | `DefaultConversationService.sendMessage` / `ActivityProjectionService.appendActivity` | Global | **Two namespaces today** (chat vs activity). Target: chat `messageId` and activity `messageId` remain distinct types but `activity.messageId` may carry `conversationMessageId` correlation when bridged (opt-in). |
| `workflowId` | workflow / project | `proj_…` (ULID today via `ProjectStore.create`) | `WorkflowOrchestrator.createProject()` | Workspace-scoped but globally unique | Synonym `projectId` in code; contract canonizes `workflowId`. |
| `taskId` | workflow task | `task_…` | `WorkflowOrchestrator.generatePlan → TaskStore.createMany` | Global | FK to `workflowId` (via `planId`). |
| `agentId` | agent definition | `agent-{slug}` / `vestara-{role}` | `AgentStorage` / `agents.registry.ts` canonical | Global | `runtimeAgent` is a *native* name (e.g. `vestara-planner`), distinct from `agentId`. |
| `threadId` | agent thread (execution container) | `thread-{epochMs}-{counter}` | `FileThreadStore.createThread()` | Global | Currently `taskId` is string-joined; target adds FK check `taskId ∈ TaskStore`. |
| `turnId` | agent turn | `turn-{epochMs}-{counter}` | `FileThreadStore.createTurn()` | Thread-scoped, globally unique | Terminal states: `completed|failed|blocked|cancelled`. |
| `runtimeSessionBindingId` | **NEW** Vestara domain session binding | `rsb_{ulid}` | `Runtime Session Authority` (new) on `bind()` transaction | Global | **Provider-neutral** primary key. Holds `openCodeSessionId` as nullable external attribute, plus `workspaceId`, `threadId?`, `workflowId?`, `conversationId?`, `agentId`. Never equals `openCodeSessionId`. |
| `openCodeSessionId` | external runtime session | `string` opaque from server (`sess_…`) | OpenCode server `POST /session` | Server-scoped | Stored only as `RuntimeSessionBinding.externalId`. Never primary key. Ephemeral; GC by server. |
| `providerId` | provider | `string` (`opencode`, `opencode-go`, `openai`, discovered ids) | `DefaultProviderManager.register` + `OpenCodeHttpClient.listProviders` | Global | Catalog entry `provider.id`. |
| `modelId` | model | `string` (`deepseek-v4-flash-free`, …) | Provider `listModels()` | Provider-scoped | Compound key `providerId/modelId` is the execution binding. |
| `executionBindingId` | provider/model execution binding token | `rb_{ulid}` (future) or `RoutingDecision.decisionId` today | `Routing Authority.resolve()` | Global | Ephemeral token proving policy pass; consumed by `Runtime Session Authority.createSession`. |
| `activityId` | activity record | `activity:{kind}:{uuid}` (or `activity:msg:{uuid}`) | `ActivityProjectionService` | Global | `sequence` is the ordering key, not `activityId`. |
| `evidenceBundleId` | evidence bundle | `bundle-{ulid}` | `EvidencePipeline.buildBundle()` | Global | CAS key; referenced by activity `evidenceRefs[]`. |

### 2.2 Identity generation rules

- No Vestara authority generates `openCodeSessionId` — it is returned by the external runtime and stored as correlation.
- `runtimeSessionBindingId` is generated **before** calling the external runtime so the Vestara transaction can commit even if the external call fails (binding row stays `status=pending`).
- `conversationId` / `workflowId` / `threadId` are generated by their respective authorities only — no cross-authority ID minting.

## 3. Identity Relationship Diagram

### 3.1 ER (cardinality, FK direction)

```
workspaceId (1) ──< conversationId (0..N)       [ConversationAuthority]
            │  └─< workflowId (0..N)            [WorkflowAuthority]
            │        │  └─< taskId (1..N)        -- via planId (plan is child of workflow)
            │        │        │  └─< threadId (0..N)   [RuntimeSessionAuthority / AgentHarness]
            │        │        │             │  └─< turnId (1..N)
            │        │        │             │        └─< threadItem (1..N)  (model-response, tool-call…)
            │        │        │             └─< runtimeSessionBindingId (0..N)  -- threadId nullable until bound
            │        │        └─< evidenceBundleId (0..N)  [EvidencePipeline] (taskId FK)
            │        └─< activityId{workflow} (0..N)  [ActivityProjection — derived]
            │        └─< activityId{acceptance} (0..1 per workflow boundary)
            │        └─< participant (0..N)  [future ParticipantStore — §10]
            ├─< runtimeSessionBindingId (0..N)  -- also directly under workspace when conversation-scoped
            │        ├─ 1 : 0..1  openCodeSessionId (external, nullable)
            │        └─ 1 : 0..1  executionBindingId (ephemeral, consumed)
            └─< routingSelection (1)  [RoutingAuthority — singleton per workspace, versioned]
                     └─< routingAssignment (0..N)  per taskId  (FileRoutingAssignmentStore)

conversationId (1) ──< messageId (1..N)  [ConversationStore]
            │  └─ 0..1 runtimeSessionBindingId  (when conversation turn executed via runtime)
            └─ ··> activityId (0..N)  dotted: optional bridge (conversation.message.sent → activity agent-message)

agentId (1)  ── derived role → RoutingAuthority.resolve({role})
         └─ metadata in threadId, runtimeSessionBindingId, task assignment
```

### 3.2 Key relationship constraints

- `workflowId` is the **correlation spine**. Every `taskId`, durable `threadId` (when workflow-scoped), `evidenceBundleId`, and `acceptance` activity **must** carry `workflowId`. `conversationId` and ad-hoc `threadId` (from `POST /api/agents/:id/runs` without workflow) carry `workflowId = null` and are excluded from organization projections.
- `threadId` may be **orphan** today (`taskId` string join, no FK). Target: `threadId` FK to `taskId` enforced at `FileThreadStore.createThread` when `metadata.workflowId` present; orphan threads remain allowed only when `workflowId == null` (explicit ad-hoc mode).
- `runtimeSessionBindingId` is the **only** join between Vestara execution and external session. Both `threadId` and `conversationId` reference it, never `openCodeSessionId` directly. `openCodeSessionId` is stored as `binding.externalIds.opencodeSessionId`.
- `providerId/modelId` pair is never stored raw on task/thread/activity as free text. The persisted form is `executionBindingId → RoutingDecisionEvidence{providerId, modelId, policyId, reasonCodes}`. Display-time lookup resolves `providerId/modelId` from the decision.
- `evidenceBundleId` correlates to activity via `activity.evidenceRefs[]` (CAS FK), and to workflow via `taskId`. Evidence bundles are never embedded.
- `messageId` (activity) may store `referencedActivityIds[]` and `correctionOf` but must never mutate the referenced record — new record with monotonic sequence.

## 4. Authority Contracts

### 4.1 Conversation Authority

**Package boundary:** `@vestara/conversation` (service) + `@vestara/conversation-runtime` (stores) + `apps/api/src/routes/conversations.ts` (HTTP facade)
**Status today:** Implemented but split across two message stores; `Intent` not on hot path. **Target restores single writer with explicit bridge.**

**Owned identity:** `conversationId` (primary), `messageId` (scoped to conversation).

**Owned state:**

```ts
Conversation {
  id: conversationId
  workspaceId
  userId               // from X-Vestara-Actor or auth principal; validated against WorkspaceMembership (future)
  title
  status: 'active' | 'archived' | 'deleted'
  createdAt, updatedAt // updatedAt = last message createdAt
}
Message {
  id: messageId
  conversationId       // FK
  role: 'user' | 'assistant' | 'tool'
  content
  providerId?, modelId? // populated by Routing decision (not raw)
  tokens?, cost?, latency?
  createdAt
}
// Persistence tables (already exist):
// conversations(id, user_id, title, status, created_at, updated_at)
// conversation_messages(id, conversation_id, role, content, provider, model, tokens, cost, latency, created_at)
```

**Lifecycle:**

```
[nonexistent] --createConversation(workspaceId, userId)--> active
active --sendMessage(user)--> active  (appends user Message, then provider turn appends assistant Message)
active --archive--> archived
archived --delete--> deleted
any --delete--> deleted  (hard: removes messages cascade — target keeps tombstone in deleted state, GC later)
```

`sendMessage` is **single-writer, turn-serialized**: one provider turn per `conversationId` at a time; second caller receives `409 conversation-busy`. Stream variant `sendMessageStream` holds same lock until terminal.

**Persistence responsibility:**

- Authoritative: `SqliteConversationStore` → `conversations.db` (`CONVERSATION_MANIFEST`). Migrations additive only.
- Cache: `DefaultConversationService.conversations: Map` is read-through cache, not source — all reads hydrate from store; map is bounded LRU (future).
- Never writes to `activity.db` directly.

**Emitted domain events (via `kernel.eventBus`):**

- `conversation.created {conversationId, workspaceId, userId}`
- `conversation.message.sent {conversationId, messageId, role, contentLength}` — emitted for **both** user and assistant appends (two events per turn).
- `conversation.provider.request.started {conversationId, executionBindingId}` — starts provider turn (contains `executionBindingId`, not raw model).
- `conversation.provider.response.completed {conversationId, messageId, providerId, modelId, latency, tokens}`
- `conversation.provider.error {conversationId, error}`
- `conversation.archived {conversationId}`
- Future (non-breaking): `conversation.bridgedToActivity {conversationId, activityId}` when opt-in bridge fires.

**Permitted callers:**

- `POST /api/conversations` (create)
- `POST /api/conversations/:id/messages` and `POST /api/conversations/:id/stream` (send) — each resolves `executionBindingId` via Routing Authority first (see §6).
- `ConversationEngine` (onboarding) — delegates to authority, does not write store directly.
- Reads: `GET /api/conversations`, `GET /api/conversations/:id` — from authority's read model.

**Forbidden responsibilities (must not own):**

- Must not choose `providerId/modelId` itself — delegates to Routing Authority and stores the decision's ids.
- Must not execute tools (`ToolRuntime.invoke`) — provider executor does; authority only persists resulting `Message`.
- Must not mutate workflow/task state, routing selection, or runtime sessions.
- Must not write to `activity.db` — bridging is via projector consuming `conversation.message.sent`, not direct store write.

**Recovery semantics:**

- **In-flight turn:** `Message` rows are written per message (user row first, assistant row after provider completes). Crash after user row + before assistant row leaves conversation with unanswered user message — `GET /:id` returns last message `role=user` with no response; next `sendMessage` succeeds (no auto-retry of provider call). Provider turn is not replayed.
- **Restart:** Rehydrate from `conversations.db` only. In-memory map is rebuilt on demand via `loadIntoMemory()`. No reconciliation with Activity Projection.
- **Idempotency:** `sendMessage` is not idempotent by payload — callers that need dedup supply `X-Idempotency-Key` header; authority stores `idempotencyKey → messageId` in new `conversation_idempotency` table (future, not AR-P1.5).

### 4.2 Routing Authority

**Package boundary:** `@vestara/provider-runtime` (`DefaultProviderManager`, `EngineeringRoutingRuntime`, `EngineeringProviderCatalog`, `FileRoutingStore`, `FileRoutingAssignmentStore`) + `apps/api/src/routes/routing.ts`
**Status today:** `FileRoutingStore` is authoritative for selection; `EngineeringProviderCatalog` is in-memory derived; per-task assignments exist but unused. **Target unifies all execution paths through this authority.**

**Owned identity:** `routingSelectionRevision` (monotonic integer), `routingAssignmentId` (derived `taskId`), `executionBindingId` / `decisionId` (`routing-{epoch}-{rand}`).

**Owned state:**

```ts
VersionedRoutingSelection {
  revision: number            // OCC
  updatedAt, updatedByClientId
  selection: {
    profileId: RoutingProfileId
    roles: Partial<Record<EngineeringAgentRole, ProviderModelRef>>  // 6 roles max
  }
}
RoutingAssignment {
  taskId
  revision
  role: EngineeringAgentRole
  agentId
  route: ProviderModelRef
  status: 'assigned'|'running'|'paused'|'completed'|'failed'
  sideEffectsRecorded
  assignedAt, assignedByClientId
  previousAssignment?
}
RoutingDecisionEvidence {
  decisionId, taskId?, agentRole, selectedAgentId
  selectedProviderId, selectedModelId, selectedModelRevision?
  reasonCodes: string[]        // ['preferred-candidate','mode:balanced',…]
  rejectedCandidates: RejectedCandidate[]
  policyId, source: 'workspace-ui'|'console'|'automatic'
  decidedAt
}
EngineeringProviderCatalogEntry {
  providerId, displayName, locality: 'local'|'cloud'
  capabilities: EngineeringCapability[]
  dataPolicies: DataPolicy[]
  modelRevisions? // empty today
}
```

**Lifecycle:**

```
Selection:  (revision N) --PATCH /api/routing/selection {selection, expectedRevision:N}--> (revision N+1)
             conflict when expectedRevision != current.revision → 409 RoutingConflictError

Assignment: (none) --POST /api/routing/assignments {taskId,role,agentId,route}--> assigned
            assigned --PATCH /status {status, expectedRevision}--> status transition (via store)
            any --POST /reassign {expectedRevision, agentId, route, reason, approved?}--> reassigned | approval-required

Decision:   ephemeral — resolve({role, agentId, taskId?, requiredCapabilities, policy, source, exclude?})
            → {selected: RoutingCandidate, evidence: RoutingDecisionEvidence}
            or throws NoCompatibleRoutingCandidateError{rejectedCandidates}
```

**Persistence responsibility:**

- **Selection:** Authoritative `FileRoutingStore` → `<workspaceDir>/routing.json` (atomic `write tmp+rename`, OCC). Single singleton per workspace.
- **Assignments:** Authoritative `FileRoutingAssignmentStore` → `<workspaceDir>/routing-assignments.json` (same atomicity).
- **Catalog:** In-memory derived from `ProviderManager.providers` + `registerEngineeringMetadata()`. Target: new `providers.json` (catalog snapshot) becomes authoritative; `FileRoutingStore` remains selection authority, not catalog (see §10 dependency).
- **Decisions:** Ephemeral by default; `RoutingDecisionEvidence` is emitted on eventBus and optionally persisted as `ActivityRecord` metadata (not a new table) for audit — stored as `activity.metadata.routingDecision`.

**Emitted domain events:**

- `routing.selection-requested {taskId?, role, policyId, source}` (before evaluation)
- `routing.candidates-evaluated {taskId?, compatibleCount, rejectedCount}`
- `routing.selection-resolved {decisionId, agentRole, selectedProviderId, selectedModelId, …}` (the `RoutingDecisionEvidence`)
- `routing.selection-overridden {revision, updatedByClientId}` (after store write)
- `routing.assignment-changed {taskId, revision, operation:'assigned'|'reassigned'}`
- `routing.execution-paused {taskId, reasonCodes}` (when `requireApprovalAfterSideEffects` gates)

**Permitted callers:**

- **Decision (resolve):** `Runtime Session Authority` (mandatory — only caller that turns a decision into a session), `Conversation Authority` (for `sendMessage`), `Workflow Authority` (when assigning `agentId→task` pre-execution, future), UI preview (`POST /api/routing/preview` — read-only, never persisted as assignment).
- **Selection mutation:** `PUT/PATCH /api/routing/selection` (editor role, OCC). No internal service writes selection directly.
- **Assignment write:** `POST /api/routing/assignments` / `/reassign` (editor), and **only** `Workflow Authority` when auto-assigning on `task.ready` (future — not in AR-P1.5).
- Forbidden callers: Activity Projection, evidence pipeline, harness context assembler — they consume `RoutingDecisionEvidence` as data, never call `resolve()`.

**Forbidden responsibilities:**

- Must not create sessions, execute completions, or hold SSE streams — delegates to Runtime Session Authority.
- Must not define `AgentDefinition` — receives `requiredCapabilities` and `role` as inputs; agent prefs are *inputs* to `preferred` field, not final selector.
- Must not write workflow/task/activty/conversation state.

**Recovery semantics:**

- Selection/assignments are **synchronously durable** (file rename is commit point). Crash mid-write leaves previous revision intact (tmp file orphan).
- Decisions are not rehydrated — `resolve()` is pure function of catalog+health+policy+selection. After restart, next `resolve()` recomputes. Health is transient.
- Health degrades availability (`available=false`) but never mutates selection — next resolve simply rejects degraded candidates with `provider-unavailable`.

### 4.3 Workflow Authority

**Package boundary:** `@vestara/workflow-orchestrator` (`WorkflowOrchestrator`, `ProjectStore`, `PlanStore`, `TaskStore`, `ArtifactStore`, `FileLockRegistry`, `WorkflowStateMachines`) + `apps/api/src/routes/orchestration.ts` / `workflow.ts` (legacy)
**Status today:** Single writer, state-machine guarded, event-sourced. **Target keeps this authority intact and makes it the only source for `workflowId→tasks→phases`.**

**Owned identity:** `workflowId` (aka `projectId`), `planId`, `taskId`, `artifactId` (changeset/review/test), `approvalId`.

**Owned state:**

```ts
OrchestratedProject {
  id: workflowId
  workspaceId
  name, goal
  repoPath
  phase: 'draft'|'analyzing'|'planning'|'architecture'|'pending-approval'|'executing'|'verifying'|'completed'|'archived'|'cancelled'
  status: derived from phase
  verificationReopens, cancelReason?, createdAt, updatedAt
}
WorkflowPlan { id: planId, workflowId, title, goal, revision, status: 'proposed'|'reviewed'|'approved'|'completed'|… }
WorkflowTask {
  id: taskId, planId, workflowId (denormalized), summary, description, files[], dependencies[], requiredCapabilities[], effort
  status: 'pending'|'ready'|'assigned'|'in-progress'|'awaiting-approval'|'reviewing'|'changes-requested'|'testing'|'approved'|'blocked'|'failed'|'cancelled'|'completed'
  assignedAgentId?, attemptCount, revisionCount, createdAt, updatedAt
}
Artifact { id, kind: 'analysis'|'plan'|'architecture'|'changeset'|'review'|'test'|'verification', workflowId, planId?, taskId?, agentId, body }
FileLock { path, holderTaskId, holderAgentId, acquiredAt }
OrchestrationEvent  // append-only audit log, not a query store
```

**Lifecycle (state machines — abbreviated):**

```
Project: draft → analyzing → planning → architecture → pending-approval → executing → verifying → completed → archived
              any except completed/archived → cancelled
         planning±architecture: can loop back on violations / needs-revision
         verifying → verifying (awaiting-approval) or re-executing (max 1 reopen), else terminal

Task: pending → ready → assigned → in-progress → (approved|changes-requested|blocked) → testing → approved → completed
               ↘ awaiting-approval → assigned (on approval) | blocked (denied)
      in-progress: on dispatch failed → retrying → (ready|blocked), on max attempts → blocked

Guard: canTransitionProject(phase, to) / canTransitionTask(status, to) in @vestara/state-machine — throws on invalid.
```

**Persistence responsibility:**

- Authoritative: `plans.db` tables (`projects`, `plans`, `tasks`, `artifacts`, `file_locks`) via `migrate(ORCHESTRATION_MANIFEST)`. Writes are transactional per transition.
- History: `SqliteEngineeringEventStore` (`engineering-events.db`) appends `OrchestrationEvent` for every mutation — the event-sourced twin. `rebuild(workflowId, events)` can reconstruct a snapshot from events alone (artifacts/locks excluded).
- Checkpoints: `workflow.checkpoint` events for wave scheduler idempotent resume.

**Emitted domain events (appended to engineering store and broadcast on `eventBus`):**

- `project.created {workflowId, name, goal}`
- `project.phase.changed {workflowId, from, to}`
- `analysis.completed {workflowId, artifactId}`
- `plan.generated {workflowId, planId, revision}` + `task.created {taskId, summary, dependencies, …}` per task
- `architecture.reviewed {workflowId, planId, status:'approved'|'violations'}`
- `plan.approved {workflowId, planId}`
- `task.ready|assigned|started|completed|failed|blocked|retrying|revision|approval-requested|approval-resolved {workflowId, taskId, planId}`
- `task.review.decided|task.tests.decided`
- `file.lock.acquired|conflict|released`
- `verification.passed|failed|awaiting-approval`, `project.completed|cancelled|verification.reopened`

**Permitted callers:**

- `POST /api/orchestration/projects` (create), `POST /api/orchestration/projects/:id/{start|analysis|plan|architecture|approve}` (phase transitions), `POST /…/execute` (run waves → threads), `POST /…/verify` (close loop), `POST …/resume` (idempotent re-entry), `POST …/tasks/:taskId/approval` (high-risk approval gate).
- Internal: `WorkflowOrchestrator.runTask` (the only caller that creates `TaskThread`s via `HarnessTaskDispatcher`).
- Reads: `GET /…/projects`, `GET /…/projects/:id` (snapshot), `GET /…/metrics`.
- **Not permitted to call directly:** Activity Projection, Routing Authority (workflow only *requests* a decision via Runtime Session Authority, not Routing directly), Conversation Authority.

**Forbidden responsibilities:**

- Must not resolve `provider/model` — delegates to Routing via Runtime Session Authority before dispatching.
- Must not execute provider completion or tool calls — delegates to `TaskDispatcher` (harness or worker).
- Must not produce `ActivityRecord` — that is Activity Projection's derived read model. Workflow emits orchestration events only.
- Must not manage participants/presence — consumes `ParticipantStore` (future) but does not own it.
- Must not decide `acceptance` content — acceptance is authored by planner/orchestrator as `AcceptanceActivity` payload, but `acceptance.boundary` evaluation remains separate (planner owns obligations).

**Recovery semantics:**

- **Idempotent resume:** `POST /…/resume` → `runExecution` re-derives `runnableTasks` from persisted `TaskStore` (completed tasks never re-executed). `computeWaves` deterministic.
- **Reconcile:** `orchestrator.reconcile(workflowId, events[])` diffs expected vs actual `TaskStatus`; report `consistent:boolean + drifts[]`. Called by diagnostics, not automatically.
- **Rebuild:** `rebuild(workflowId, events, {workspaceId, repoPath})` reconstructs `ProjectSnapshot` from event log alone (no DB read) for auditing.
- Crash between store write and event append: `reconcile()` detects; operator may re-emit missing event or re-run `resume` — never automatically mutates store to match derived view (I-6).

### 4.4 Runtime Session Authority  (NEW — the provider-neutral seam)

**Package boundary:** New `packages/runtime-session` (target) or collateral in `@vestara/opencode-runtime` + `apps/api/src/opencode-runtime-service.ts` refactored. In AR-P1.5 this authority is *specified*, not implemented — legacy `OpenCodeRuntimeProvider` remains behavior-identical but is reclassified as `Runtime Adapter`, not authority.
**Motivation:** Today `InMemorySessionRegistry` is ephemeral and `OpenCodeRuntimeProvider.complete()` creates/aborts a server session per turn — no Vestara identity. This authority makes sessions domain-owned and external IDs correlation-only.

**Owned identity:** `runtimeSessionBindingId` (primary, `rsb_*`), `externalId` (nullable `{provider:'opencode', sessionId: openCodeSessionId}`).

**Owned state:**

```ts
RuntimeSessionBinding {
  id: runtimeSessionBindingId
  workspaceId
  workflowId?            // when workflow-scoped
  conversationId?        // when conversation-scoped (mutual exclusive with workflowId? no — may be both null for ad-hoc harness thread)
  threadId?              // when harness-scoped (nullable until thread created)
  turnId?                // last turn using this binding (nullable)
  agentId                // logical agent (e.g., vestara-developer)
  executionBindingId     // FK to RoutingDecisionEvidence.decisionId
  externalIds: {
    opencodeSessionId?: string   // nullable until server creates
    opencodeProjectDirectory?: string // cached project.directory at bind time
  } | null
  status: 'pending'|'bound'|'active'|'idle'|'error'|'closed'|'orphaned'
  // pending = Vestara row committed, external create not yet ack'd
  // bound   = external session returned, awaiting first completion
  // active  = streaming
  // idle    = server signaled session.idle, not yet aborted/GC'd
  // closed  = Vestara aborted (per-turn today)
  // orphaned= server still holds session but Vestara lost binding (GC marker)
  createdAt, updatedAt, closedAt?
  createdBy: string      // actor id (human or agentId)
  correlationId: string  // same as Activity turn correlationId for join
}
ExecutionBinding {       // view of RoutingDecisionEvidence materialized at bind time
  executionBindingId
  providerId, modelId, modelRevision?
  policyId, reasonCodes[]
  routingRevision        // selection revision at decision time
}
```

**Lifecycle:**

```
(bound before external create)
[none] --bind({workspaceId, agentId, executionBindingId, workflowId?, threadId?})--> pending
pending --onExternalCreate({openCodeSessionId})--> bound
bound --onStreamStart--> active
active --onIdle--> idle
idle --abort()--> closed                 // today's per-turn finally()
active --onError--> error --abort()--> closed
any --onOrphanDetected--> orphaned --gc()--> closed
pending --onExternalCreateFailed--> error

Recovery: pending rows with externalIds==null are retried once on restart (re-bind attempt);
          bound/active rows whose external session no longer exists on server (GET /session/:id 404) → orphaned.
```

In AR-P1.5 target, per-turn `create→abort` remains (no affinity), but every turn now has a `RuntimeSessionBinding` row so the mapping is queryable and GC'd. Future AR-P2 may introduce `affinity: 'per-workflow'` policy reusing one binding across turns of same workflow (migration, not AR-P1.5).

**Persistence responsibility:**

- Authoritative: **new table(s)** `runtime_session_bindings` + `execution_bindings` in `threads/agent-harness.db` (co-located with turns for transactional `createThread → bind` atomicity) or in dedicated `runtime.db`. AR-P1.5 specifies schema/migrations but **does not run them** — legacy `InMemorySessionRegistry` continues to serve AR-P1.5 runtime.
- Durable, append-then-update (status mutations are updates, not appends — id row mutated, audit via engineering events).
- No credential storage — `opencodeSessionId` is the only external secret-adjacent id and is treated as correlation, never logged beyond `activity.metadata.correlationId`.

**Emitted domain events (new, via `eventBus`):**

- `runtime.session.binding.created {bindingId, workspaceId, agentId, executionBindingId, workflowId?, threadId?}`
- `runtime.session.external.bound {bindingId, openCodeSessionId, providerId, modelId}`
- `runtime.session.stream.started {bindingId, turnId}`
- `runtime.session.stream.completed {bindingId, turnId, durationMs}`
- `runtime.session.stream.failed {bindingId, turnId, error, statusCode}`
- `runtime.session.closed {bindingId, reason: 'completed'|'cancelled'|'orphan_gc'}`
- `runtime.session.orphan.detected {bindingId, lastSeenAt}`

All events carry `correlationId = binding.correlationId = turn.correlationId` so a single join key links `ThreadItem`, `EngineeringEvent`, `ActivityRecord`, and `EvidenceBundle`.

**Permitted callers:**

- **Creator:** Only `Runtime Session Authority.bind()` is called by the single facade `createExecutionSession({workspaceId, agentId, threadId?, conversationId?, executionBindingId})` which atomically:
  1) calls `RoutingAuthority.resolve()` to obtain `executionBindingId` (if not supplied),
  2) persists `RuntimeSessionBinding(status=pending)`,
  3) calls the `Runtime Adapter` (today `OpenCodeRuntimeProvider`) to get `openCodeSessionId`,
  4) persists `status=bound` + `externalIds`.
- **Consumers of binding:** `AgentHarnessRuntime.continueTurn()` (receives `bindingId` before provider call), `Conversation Authority` streaming path, `EvidencePipeline` (for bundle correlation).
- **Queries:** `requireSessionOwnership(registry, bindingId, {workspaceId, userId})` — must use `bindingId`, never raw `openCodeSessionId`.
- No direct `OpenCodeHttpClient.createSession` from callers other than this authority's adapter.

**Forbidden responsibilities:**

- Must not choose `provider/model` — consumes `executionBindingId` from Routing, never inspects `providerId` except to pass to adapter.
- Must not own workflow/task state — holds `workflowId/threadId` as FK, never mutates them.
- Must not project to Activity — emits `runtime.session.*` events; Activity Projection derives `agent-message` / `verification` records.
- Must not store credentials — `OPENCODE_SERVER_URL/PASSWORD` stays in `resolveOpenCodeConfig()` config layer; authority only receives an authenticated `OpenCodeClient` via DI.

**Recovery semantics:**

- **Crash after Vestara `bind.pending` before external create:** On restart, `pending` bindings older than `bindTimeoutMs` are marked `error` and retried once if still `pending` (idempotent external create via `client.createSession` with `X-Idempotency-Key=bindingId`).
- **Crash after `bound` before `idle`:** Next `AgentHarnessRuntime.resume(threadId)` discovers `binding.status=active` and calls `adapter.recover(binding.externalIds.opencodeSessionId)` — either streams till `idle` or marks `failed`. Activity for that turn shows `status=error` + evidence bundle with `reason: orphan_recovery`.
- **Orphan GC:** Periodic `listSessions()` from server diffs against Vestara `bound|active` rows — missing server sessions become `orphaned`, then closed. No leaked sessions remain after GC sweep.

### 4.5 Activity Projection Authority (Derived, Append-Only)

**Package boundary:** `@vestara/activity-projection` (`ActivityProjectionService`, `ActivityProjectorRegistry`, `ActivityRedactor`, `SqliteActivityStore`, `ActivityStreamHub`, `ActivityStreamConnection`) + `apps/api/src/bridges/activity-room-organizational-bridge.ts` + `apps/api/src/routes/activity-room.ts`
**Status today:** Correctly derived/append-only but whitelist-filtered and ledger semantics mix `A` physical with `D` semantic. **Target freezes derived semantics and hardens whitelisting.**

**Owned identity:** `activityId` (+ `sequence` monotonic). No other identities are owned — all others are foreign keys (`workflowId`, `taskId`, `threadId`, `agentId`, etc.).

**Owned state (persisted read model):**

```ts
ActivityRecord  // discriminated union, already typed in contracts.ts
  WorkflowActivity  { workflowId, previousState, currentState, reason, authoritative, observed }
  TaskActivity      { taskId, previousStatus, status, summary? }
  AgentMessageActivity { agentId, threadId?, turnId?, messageKind, content, toolName?, risk?, referencedActivityIds? }
  TestActivity      { taskId?, command, passed/failed/skipped, failureFingerprints, outputExcerpt? }
  VerificationActivity { verificationRunId?, taskId?, outcome, confidence?, checks[] }
  AcceptanceActivity { workflowId, objective, obligations[], materialUncertainties[], conditional, derivedBy }

ActivityBase       { id, sequence, timestamp, actor, workflowId?, sessionId?, taskId?, correlationId?, evidenceRefs[], effect?, relatesTo?, correctionOf? }

Store meta: lastSequence(): number, list(ActivityQuery): ActivityPage{records[], nextSequence?}
```

Store supports `append(record)` only — `DuplicateActivityError` on id collision; history never mutated. `withSequence(record, allocate())` assigns sequence after redaction, before persist.

**Lifecycle:** No state machine — activity is an event log. Corrections are new records with `correctionOf: originalActivityId` and `effect:'intervention'`, not updates. `projectEffectiveState(records)` folds current effective open items in memory.

**Persistence responsibility:**

- Authoritative **for its own history**: `SqliteActivityStore` → `.vestara/activity.db` (`ACTIVITY_MANIFEST`). History is durable, replayable, and the source for recovery (history-first hub attach → backfill pages).
- **Derived semantically**: every `ActivityRecord` is the output of a pure projector `supports(event) → project(event)` over a source domain event. No domain state originates here.

**Emitted domain events / transport:**

- Transport-only: `ActivityStreamHub.broadcast(record)` → WS `activity.appended{sequence, activity}` per attached `ActivityStreamConnection`.
- `activity.resync-required{earliestAvailableSequence, latestSequence}` on buffer overflow (`capacity:128`).
- History is served via `GET /api/activity-room?afterSequence=N&limit=100` (polling recovery) — not an event.

**Permitted callers (writers):**

- **Only:** `ActivityProjectionService.project(sourceEvent)` and `appendActivity(humanMessageRecord)`. Call sources:
  - `startActivityRoomOrganizationalBridge` subscribing `eventBus:*` for `workflow.*` / `acceptance.boundary` / `harness.*` / `opencode.execution.activity` (via execution→harness translation).
  - `HarnessEngineeringEventBridge` (today also appends to `engineeringEvents` — that bridge remains, but Activity Projection does not call it).
  - `POST /api/messages` / `POST /api/agents/:id/messages` human ingress (direct `appendActivity` after redaction+sequence; no domain event pre-step — this is the one ingress that is *both* source and projection, kept for AAR-001E).
- Reads: `GET /api/activity-room`, `GET /api/activity-room/:id`, `GET /api/activity-room/state` (effective), `GET /api/activity-room/messages/:messageId/receipts` (but receipts themselves move to durable store — activity only serves the message activity).

**Forbidden responsibilities (hard freeze):**

- **Must never** `UPDATE` / `DELETE` any `activity.db` row, nor mutate a referenced record when `correctionOf` is set — append new record only.
- Must never own or mutate **workflow phase/task status, routing selection, runtime session status, conversation status, participant/presence lifecycle, approval decisions, or acceptance obligations**. It may *project* `workflow`/`task`/`acceptance` activities but never decide them.
- Must never decide `@mention` attention — it stores `AgentMessageActivity` with `workflowId/agentId` but receipts/presence are owned elsewhere (future `ParticipantStore` / durable receipts). The `messageTargetsAgent` heuristic moves out of activity.
- Must never choose provider/model or own tool approvals — those are harness/orchestrator concerns projected as `tool-call/result`.
- Must never persist credentials, `evidenceBundle` bytes (only `evidenceRefs[]` FK), or PII that `ActivityRedactor` strips.

**Recovery semantics:**

- **History-first:** On `WS /ws/activity` `activity-subscribe{afterSequence}`, hub `attach(id, sink, frontier=lastSequence)` first, then paged backfill `store.list({afterSequence: cursor, limit:1000})` until `nextSequence==undefined`. Because attach precedes backfill, live records appended during backfill are held in `pending` and delivered *after* history — no gap (fix from audit T10).
- **Buffer overflow:** `pending.length > capacity` → `resync-required` + `detach(id)`; client must re-subscribe from fresh checkpoint via history poll. Deterministic.
- **Store durability on crash:** `activity.db` is the truth; hub state (`pending`, `checkpoint`) is ephemeral and reconstructed per connection. No hub state is ever committed.

## 9. Migration Dependency Order (specification only — no migrations run in AR-P1.5)

Dependencies reflect that a downstream migration must see the upstream authority's schema or contract before it is useful. All migrations are additive, reversible via event rebuild, and gated by AR-P2 feature flags.

```
Tier 0 — Foundation (no authority change, enable observability)
  M0a  Instrument: emit RoutingDecisionEvidence on every existing resolve path (no behavior change, audit coverage)
  M0b  Instrument: emit runtime.session.* events from current OpenCodeRuntimeProvider (shim, non-durable)
  M0c  Add correlationId to every ThreadItem + every engineering event missing it (backfill via ThreadItem.correlationId)

Tier 1 — Routing is sole selector (enforces I-3)
  M1   Facade: introduce ExecutionResolverFacade wrapping EngineeringRoutingRuntime.resolve()
       Gate: harness continueTurn + conversation sendMessage must call facade
       Pre: M0a
       Blocks: M2

Tier 2 — Runtime Session becomes domain-owned (provider-neutral)
  M2a  Schema: CREATE runtime_session_bindings + execution_bindings (THREAD_MANIFEST extension)
       Persist binding row before external create; store openCodeSessionId as externalIds
       Pre: M1 (needs executionBindingId FK)
  M2b  Durable ownership: replace InMemorySessionRegistry reads with binding table reads; requireSessionOwnership checks bindingId
       Pre: M2a
  M2c  GC: orphan sweep (diff server /session list vs bindings bound|active) + abort idempotency
       Pre: M2b

Tier 3 — Participant / Receipts durable (enables correct @mention + presence)
  M3a  ParticipantStore (workspaceId, workflowId, agentId, role, joinedAt) — populated from ThreadStore + Orchestrator task assignments
       Pre: M2a (threadId→workflowId FK available)
  M3b  Durable receipts: activity_receipts {messageId, agentId, state, observedAt} replacing in-memory Map
       Generator: registerMessage seeds receipts from ParticipantStore; markObserved from context assembler via store
       Pre: M3a
  M3c  Presence: presence heartbeats from /ws and /ws/worker merged into ParticipantStore.presenceStatus
       Pre: M3a

Tier 4 — Workflow integrity hardening
  M4a  Enforce threadId FK: createThread({taskId}) validates taskId ∈ TaskStore when workflowId present
       Pre: M3a
  M4b  Reconcile/rebuild automation: POST /api/orchestration/projects/:id/reconcile runs on boot for dirty projects
       Pre: (none logical) but after M3b for clean participant view

Tier 5 — Optional bridges (non-breaking)
  M5a  Conversation → Activity bridge (opt-in per workflow): conversation.message.sent → ActivityRecord agent-message with conversationId correlation
       Pre: M3b (needs participant resolution)
  M5b  Single recovery contract deprecation signal: emit Deprecation header on /ws activity-style events, guide clients to /ws/activity
       Pre: (independent)
```

## Appendix C — Glossary

- **Authority** — single writer for a domain fact (per I-1). Not necessarily the only reader.
- **Projection** — read model derived by pure functions over authoritative history. May be durable (activity.db) but never mutated to drive authority.
- **Binding** — durable FK row linking Vestara identities to each other (and optionally to an external runtime id).
- **Execution binding** — the token representing a successful `RoutingAuthority.resolve()` decision; consumed to create a Runtime Session Binding.
- **Correlation** — `{correlationId, workflowId, taskId, threadId, turnId, bindingId, openCodeSessionId, bundleId}` traceable path through an operation for audit.
- **Orphan** — external session that still exists on the server but whose Vestara binding row is missing/closed (GC candidate).
